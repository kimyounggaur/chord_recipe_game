# 코드 레시피 키친 검수 기록

2026-11-12. 구현 검수 대상: 현재 저장소의 1.0.0 소스. 브라우저 QA는 Sites local preview, Chromium, CSS viewport 1363×936 및 확대에 의한 340×234. 실기기 Android/iOS 검수와 다르다.

## 실제 실행 결과

- 음악 엔진 독립 fixture 18개: 네 3화음, D 전이, B/F♯ 옥타브, C♭/B♯/겹임시표, 12×4 불변식, 24개 데이터 기대값.
- 학습 상태 테스트 18개: 실제 입력 가드, 오답 보존, 근음/맨 위 음 고정 변형, minor 확인, 비교/질문 가드, terminal 재개, 혼합 H0, 입력 유효성, 자유 탐색 표기.
- Web Audio 모의 테스트 5개: resume 대기 정지, 실제 마지막 음 종료, 연타와 과거 콜백, 음소거/음량0, 잘못된 MIDI.
- 저장 테스트 7개: 백업 round-trip, 가져오기/범위/미래버전 검증, 도장 병합, 손상·quota·예외 복구, 혼합 순서, 명시적 이전 버전 이행.
- 서비스워커 VM 테스트 5개: Vite 청크 캐시, offline cache hit, 명시적 업데이트, 앱 캐시만 정리, 최초 offline 설명.
- 합계 53개 자동 검사. 최종 실행 명령: npm test, npm run typecheck, npm run lint(현재 TypeScript 검사), npm run build.

## 브라우저에서 직접 수행한 흐름

1. 소리 없이 시작→C4→D♯4 오답→E4→G4. 오답이 C를 지우지 않았고 실제 3/목표4반음 피드백을 확인했다.
2. 장3화음의 시각 확인→저장→E를 한 반음 내려 E♭→두 간격 3+4→A/B 시각 비교→구조 질문→첫 튜토리얼 완료.
3. 새로고침→이어하기로 완료 상태13 복원, 레시피북의 C major/C minor와 정확한 간격 복원.
4. L04~L22를 실제 슬롯/건반으로 입력·제출·정답 구조 질문·다음 주문으로 완료. G/F/A/B♭의 옥타브 변경, 한 음 수리, 감·증3화음 포함.
5. L23 네 문항 중 두 문항을 끝내고 새로고침→이어하기. 3/4로 재개하여 나머지 두 문항 완료.
6. L24에서 가운데 음만 고친 후 제출: 미완료와 맨 위 음의 실제4/목표3반음 안내. G를 G♭로 고친 후 완료. 홈에서 24/24 확인.
7. 룰북 12장면 모두 이전/다음 접근. D 전이 장면의 직접 해보기→레시피 펼치기→데모 끝내기로 원래 홈/룰북 복귀. 진도는24/24 유지.
8. 자유 연습의 레시피 펼치기와 음원 재생. 소리 켜기 후 함께 듣기→재생 정지 버튼 표시→실제 재생 종료 후 ✓함께 듣기 상태 확인. 이는 오디오 엔진 재생 상태 검수이며 음색에 대한 사람의 청감 평가는 아니다.
9. 확대300~400%에서 CSS 폭454/340px 반응형 확인. 340px 폭에서 document scrollWidth337px: 전체 가로 넘침 없음. 건반·슬롯·레시피 펼치기 버튼 조작. 짧은 높이는 자연 스크롤.

## 성능과 검증 한계

사용자 요청대로 생성 PNG와 설명 원본을 byte-identical로 보존했다. 원본7종 합계12,660,764바이트로 전체 에셋은 1.5MB 첫 전송 목표를 초과한다. 룰북 원본은 해당 화면에서만 로딩하며, 다운로드한 에셋은 캐시한다. 이미지 축소/재압축을 임의로 시행하지 않았다. 입력100ms 목표는 실측하지 않았고 보장 수치로 보고하지 않는다.

Android Chrome/iOS Safari 실기기, WebKit, 완전한 스크린리더, 실제 오프라인 전환/설치는 미검증이다. DevTools는 실행 환경 정책으로 사용할 수 없었으며 다른 경로로 우회하지 않았다. 브라우저 로그의 확장 프로그램 metadata 오류는 앱 소스 오류와 구분했다.

출시를 막는 재현된 음악 오답 승인/진도 손실/주요 모드 조작 불가 P0/P1은 수정했고 자동 검사와 실제 위 흐름을 재검증했다. 나열하지 않은 기기·환경까지 검증 완료라고 주장하지 않는다.
